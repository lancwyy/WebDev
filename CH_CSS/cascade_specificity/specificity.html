CSS Specificity Scoring System

Specificity（選擇器特異性）用來比較相同 Cascade 層級中的 CSS 規則。以下使用 (ID, class, type) 三欄計分，逐欄由左至右比較；較左欄較大時，右邊欄位再大也不能勝過它。此分數只計算選擇器中的項目。

計分欄位

選擇器種類 計分內容 例子
ID ID 選擇器數量。 #menu → (1, 0, 0)
Class Class、attribute、pseudo-class 選擇器數量。 .active、[disabled]、:hover 各加一個 class 分數
Type Type（元素）與 pseudo-element 選擇器數量。 article、::before 各加一個 type 分數

例如 #menu .item li 的分數是 (1, 1, 1)：一個 ID、一個 class、一個 type。Selector specificity 不包含 HTML 屬性，也不會將 CSS 宣告本身計入分數。

常見選擇器的計分

選擇器 分數（ID, class, type） 原因
* (0, 0, 0) Universal selector 不計分。
li (0, 0, 1) 一個 type selector。
.nav .active (0, 2, 0) 兩個 class selector。
#main .nav a:hover (1, 2, 1) 一個 ID、兩個 class/pseudo-class、一個 type。
ul > li.active (0, 1, 2) 組合子（此處為 >）不計分。
:not(.disabled) (0, 1, 0) :not() 本身不計分，參數中的選擇器計分。
:is(#main, .panel) (1, 0, 0) :is() 取參數清單中特異性最高的選擇器。
:where(#main, .panel) (0, 0, 0) :where() 與其參數一律不增加特異性。

:has() 和 :not() 一樣，本身不增加分數，會採用參數中最高的特異性。逗號分隔的 selector list 則是各選擇器分開計分；不能把整份清單當成一個選擇器累加。

比較方式：逐欄比較，不是總和

(1, 0, 0) 勝過 (0, 99, 99)，因為先比較 ID 欄。不能把分數加總成一個數字，也不存在「十個 class 就等於一個 ID」的進位規則。

HTML

<p id="id-wins" class="notice">ID selector 勝過 class + type selector</p>

CSS

#id-wins { color: red; }  /* (1, 0, 0) */
p.notice { color: blue; } /* (0, 1, 1) */

結果：紅色，因為 (1, 0, 0) 高於 (0, 1, 1)。

:is() 取最高參數分數

:is(#is-target, .is-fallback) 的分數取參數中較高者，也就是 ID 分數 (1, 0, 0)。即使另一條規則較晚出現，這條規則仍勝出。

HTML

<p id="is-target" class="is-demo">:is() 的 ID 參數提高分數</p>

CSS

:is(#is-target, .is-fallback) { color: purple; } /* (1, 0, 0) */
p.is-demo { color: blue; }                         /* (0, 1, 1) */

結果：紫色，:is() 參數中的 ID 參與計分。

:where() 不增加分數

p:where(#where-target) 只有 p 計入分數，結果為 (0, 0, 1)。即使參數有 ID，:where() 仍固定為零；所以 class 規則勝出。

HTML

<p id="where-target" class="where-demo">:where() 不增加特異性</p>

CSS

p:where(#where-target) { color: red; } /* (0, 0, 1) */
.where-demo { color: blue; }           /* (0, 1, 0) */

結果：藍色，class 規則的特異性較高。

特異性相同時，比較 source order

當兩條適用規則的 origin、importance、layer 和 specificity 都相同時，後出現的宣告勝出。

HTML

<p class="source-order">同分時由後面的規則勝出</p>

CSS

.source-order { color: red; }   /* (0, 1, 0)，先出現 */
.source-order { color: green; } /* (0, 1, 0)，後出現 */

結果：綠色，兩條規則同分，後出現者勝出。

Specificity 不是 Cascade 的第一步

先比較 origin、importance 和 layer 等 Cascade 條件，再於適用的同一層級比較 specificity。因此低特異性的作者 !important 可以勝過高特異性的作者一般宣告。

HTML

<p id="important-target" class="low-specificity-important">重要宣告勝過一般宣告</p>

CSS

#important-target { color: blue; }              /* (1, 0, 0)，一般宣告 */
p.low-specificity-important { color: red !important; } /* (0, 1, 1)，!important */

結果：紅色；先比較 importance，再比較 specificity。

快速檢查

  • 先確認兩條規則真的都適用於同一元素及同一屬性。
  • 先比較 Cascade 的來源、重要性和 layer；不要把 specificity 當成唯一規則。
  • 以欄位由左至右比較 specificity；不要加總分數。
  • 若 specificity 相同，再看 source order（以及適用時的其他 Cascade 規則）。
