    二、prototype 和 __proto__ 不是同一個東西
    
    
    
      
    
        
      
    
      
    
        
    Dog.prototype只有能用 new 呼叫的函式（一般 function、class）才有；箭頭函式和物件方法簡寫都沒有。意思是：「之後用 new Dog() 做出來的物件，原型要指向我。」
    
        
    d.__proto__每個物件都有。意思是：「我找不到屬性時，下一站去哪裡找。」正式寫法是 Object.getPrototypeOf(d)。
    
        
    Object.getPrototypeOf(d) === Dog.prototype結果是 true。兩條路指向同一個物件。
    
        
    口訣：prototype 是模具上的設定，__proto__ 是成品身上的連結。
    
      
    
    
    
    
    每個物件都有原型，差別只在指向誰
    
    
    
      
    
        
    建立方式範例[[Prototype]] 指向物件本身有 .prototype？
    
        
          
    Object literalconst a = {}Object.prototype沒有
    
          
    Object.create(p)const b = Object.create(a)p（這裡是 a）沒有
    
          
    new F()const d = new Dog()F.prototype沒有
    
          
    Object.create(null)const e = Object.create(null)null（真正沒有原型）沒有
    
          
    一般 function / classfunction Dog() {}Function.prototype有，給 new 用
    
          
    箭頭函式、方法簡寫() => {}、{ m() {} }Function.prototype沒有（不能 new）
    
            
      
    
    
    
  
    

  
    
    
    三、方法要放在哪裡？
    
    
    同一個 bark 方法有三個地方可以放。按「new 一隻狗」，看看每多一個實例，各種寫法會多出幾個函式。
    
    
    
    
    
      
      
      
    
    
    
    
      
    
        
    ① 建構函式內
    
        
    掛在 this 上
    
        this.bark1 = function () {…}
        
    
          
    實例拿得到？
    可以，是實例自己的屬性
    
          
    函式數量
    2每隻狗各一份
    
          
    適合
    每個實例確實需要不同函式時
    
        
    
        
    
        
    a.bark1 === b.bark1 → false
    
      
    
      
    
        
    ② 函式物件本身
    
        
    掛在 Dog 上（static）
    
        Dog.bark2 = function () {…}
        
    
          
    實例拿得到？
    不行，Dog 不在實例的原型鏈上
    
          
    函式數量
    1屬於類別本身
    
          
    適合
    工具方法，例如 Array.isArray()
    
        
    
        
    
        
    a.bark2 → undefined　Dog.bark2() → "汪"
    
      
    
      
    
        
    ③ 原型物件標準做法
    
        
    掛在 Dog.prototype 上
    
        Dog.prototype.bark3 = function () {…}
        
    
          
    實例拿得到？
    可以，沿原型鏈往上找到
    
          
    函式數量
    1所有實例共用
    
          
    適合
    實例方法的預設位置
    
        
    
        
    
        
    a.bark3 === b.bark3 → true
    
      
    
    
    
    
    
      
    
        
    為什麼不讓實例直接連到 Dog？
    
        
    new 設定的連結是 a → Dog.prototype，不是 a → Dog。這是刻意的設計：函式物件本身已經有 name、length、call、bind 等屬性。如果實例直接繼承 Dog，忘了設定 this.name 時，a.name 會變成 "Dog"。
    
        
    所以 JS 另外準備一個乾淨的 Dog.prototype 給實例共用：Dog 自己的屬性給類別用，Dog.prototype 的屬性給實例用。
    
        
    prototype 是連結，不是複製。之後執行 Dog.prototype.sit = …，早就建立的實例也能立刻呼叫 a.sit()。
    
      
    
      
    
        
    對應到 class 語法
    
        
    
        
    class field 加箭頭函式常用來綁定 this（例如 React 事件處理），代價是它屬於 ①，每個實例各一份。

    五、帶走這五件事
    
    
      
      
    • 讀取會往上找自己沒有就問原型，一路問到 null，最後得到 undefined。
      • 
      
    • 寫入只寫自己obj.x = 1 會在 obj 自己身上建立 x，遮住上層同名屬性，不會改到原型。
      • 
      
    • 方法放原型上共用資料放在每個實例上，方法放在 prototype 上，所有實例共用同一份函式。
      • 
      
    • 函式本身的屬性是 staticDog.xxx 不在實例的原型鏈上，實例拿不到，要用 Dog.xxx() 呼叫。
      • 
      
    • class 只是語法糖extends 就是把兩個 prototype 接成一條鏈。
